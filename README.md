## 🖼 사용자가 보는 화면 (UI/UX)

앱을 켜면 **어떤 순서로 어떤 화면**이 나오는지 흐름으로 정리

### 📌 전체 화면 흐름 (비유: 건물 입장 → 층별 안내)

```
앱 실행
   ↓
[준비 중...] 로딩 화면 (잠깐)
   ↓
이미 로그인했나요?
   ├─ 예 → 🏠 홈 (저장된 플랜, 개인 기록 요약)
   └─ 아니오 → 🔐 로그인 화면
                  ↓
            회원가입 / 로그인 / 카카오 로그인
                  ↓
            로그인 성공 → 🏠 홈으로 이동
```

홈에서 사용자는 **새 플랜 만들기**, **사진으로 기록**, **내 기록 보기** 등 버튼을 눌러 다음 화면으로 이동합니다.

---

### 1️⃣ 로그인·회원가입 (`/login`, `/signup`)

| 구분          | 설명                                                                                    |
| ------------- | --------------------------------------------------------------------------------------- |
| **보이는 것** | 이메일·비밀번호 입력창, 로그인/회원가입 버튼, 카카오 로그인 버튼                        |
| **UX**        | 회원가입 시 이메일 인증 코드 입력 → 닉네임·비밀번호 설정 후 가입 완료                   |
| **비유**      | 건물 **출입증 발급처**. 여기서 계정을 만들거나 이미 있는 출입증(로그인)으로 들어갑니다. |

---

### 2️⃣ 홈 (`/(tabs)` — 첫 번째 탭)

| 구분          | 설명                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **보이는 것** | 상단 헤더(사용자 이름, 로그아웃), **히어로 카드**(지금 만들 코스 또는 최근 플랜 요약), "저장된 플랜" 카드 목록, "개인 기록" 카드 목록 |
| **UX**        | "새 플랜 만들기" → 코스 조건 입력 화면으로 / "사진으로 기록" → 업로드 화면으로 / "내 기록" → 스팟·플랜 목록으로                       |
| **비유**      | 집 **현관문 들어서 보이는 대시보드**. 오늘 일정·최근 기록이 한눈에 보이는 알림판입니다.                                               |

---

### 3️⃣ 코스 조건 입력 (`/course`)

| 구분          | 설명                                                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **보이는 것** | 지역, 날짜·시간, 이동수단, 카테고리(관광/맛집 등), **고정 일정**(점심·미팅 등), 지도에서 고른 장소 목록(드래그로 순서 변경), "코스 생성하기" 버튼 |
| **UX**        | 지도에서 장소 검색 → 선택 시 리스트에 추가 → 드래그로 순서 변경 → 조건 다 넣고 생성 버튼 클릭 → 잠시 로딩 후 "추천 결과" 탭으로 자동 이동         |
| **비유**      | **여행사 양식 작성**. "언제, 어디서, 뭘 타고, 꼭 가야 할 곳은?"을 적어 넣으면, 뒤에서 AI가 일정표를 만들어 줍니다.                                |

---

### 4️⃣ 추천 결과 (`/(tabs)/results` — 두 번째 탭)

| 구분          | 설명                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **보이는 것** | **일차 탭**(Day 1, Day 2, …), **타임라인**(장소 카드 + 도착 시간 + 이동 수단 + 혼잡도 🟢🟡🔴), 오른쪽 **지도**(마커·경로선) |
| **UX**        | 일차 탭 클릭 시 해당 날짜 타임라인만 표시, 편집 모드에서 장소 삭제·대체 추천 가능, "저장" 버튼으로 플랜 저장                |
| **비유**      | **인쇄된 여행 일정표 + 지도**가 한 화면에 있는 것. 장소별로 "몇 시에 도착, 뭘 타고, 혼잡해?"가 보입니다.                    |

---

### 5️⃣ 사진 업로드·장소 등록 (`/upload`)

| 구분          | 설명                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| **보이는 것** | 사진 선택(갤러리), 선택한 사진 미리보기, 위치 자동 인식 시 주소 표시, 위치 없으면 지도에서 수동 선택 |
| **UX**        | 사진 선택 → EXIF로 위치 자동 채움(또는 수동 입력) → "장소로 저장" 시 개인 기록(스팟)으로 등록        |
| **비유**      | **사진 한 장 넣으면 "여기서 찍었네요"** 하고 주소까지 채워 주는 기록장.                              |

---

### 6️⃣ 스팟 상세·내 기록 (`/record`, `/records`)

| 구분          | 설명                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------- |
| **보이는 것** | 스팟 상세: 사진, 이름, 주소, 메모, 지도 / 내 기록: 스팟 목록·저장된 플랜 목록 탭, 일괄 선택·삭제  |
| **UX**        | 스팟에서 메모 수정 가능, 관련 여행 플랜 목록 표시, 기록 목록에서 삭제·상세 보기                   |
| **비유**      | **다녀온 곳 엑셀 + 지도**. 한 장소씩 눌러서 메모 보기·수정하고, 플랜과 연결된 기록을 모아 봅니다. |

## 🧩 화면을 이루는 컴포넌트 구조

**컴포넌트**는 화면을 이루는 **블록 하나하나**라고 보면 됩니다.  
(비유: 레고 블록 — 작은 블록을 조합해서 화면 한 장이 만들어집니다.)

### 📂 폴더별 역할

| 폴더              | 역할 (쉽게 말하면)                                                                 | 대표 예시                                                  |
| ----------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **`app/`**        | **"어떤 URL에 어떤 화면을 보여줄지"** 정의. 파일 하나 = 경로 하나.                 | `login.tsx` → `/login`, `(tabs)/index.tsx` → 홈            |
| **`screens/`**    | **화면 전체 레이아웃**. 한 페이지의 뼈대와 섹션 배치.                              | `CourseScreen`, `ResultsScreen` (웹용·앱용 파일 분리 가능) |
| **`components/`** | **여러 화면에서 재사용하는 부품**. 버튼, 지도, 로딩, 모달 등.                      | `SpotMap`, `LoadingSpinner`, `ConfirmModal`                |
| **`contexts/`**   | **앱 전체에서 쓰는 "공유 데이터"** (로그인 여부, 코스 결과 등). 아래에서 자세히.   | `AuthContext`, `PlacesContext`                             |
| **`services/`**   | **백엔드 API 호출**. "로그인해줘", "코스 생성해줘" 같은 요청을 서버에 보내는 코드. | `authService`, `planService`                               |

### 🔀 화면이 그려지는 순서 (비유: 레고 쌓기)

1. **`app/_layout.tsx`**  
   앱이 켜지면 맨 먼저 실행됩니다. **Provider**(공유 상태 컨테이너)로 전체를 감싸고, 그 안에 모든 화면을 넣습니다.  
   → "건물의 **골조**를 먼저 세우고, 그 안에 층(화면)을 넣는 것"과 같아요.

2. **`app/index.tsx`**  
   "지금 로그인했는지" 확인하고, **로그인됐으면 홈**, **안 됐으면 로그인 화면**으로 보냅니다.  
   → **문지기**가 "출입증 있으면 홈, 없으면 로그인 창"으로 안내하는 것.

3. **`(tabs)/_layout.tsx`**  
   하단에 **홈 | 추천 결과** 탭을 만듭니다.  
   → **층별 안내판**. "1층(홈), 2층(결과)"를 고를 수 있게 해요.

4. 각 **`app/경로.tsx`**  
   해당 경로로 들어왔을 때 **어떤 Screen/컴포넌트**를 보여줄지 정합니다.  
   → **방 문 앞에 붙은 이름표**. "이 방은 코스 입력실", "이 방은 결과실"처럼요.

### 📱 웹 vs 앱 (플랫폼별 분리)

같은 기능이라도 **웹**과 **앱**에서 쓰는 라이브러리가 다를 수 있어요.  
그래서 같은 이름의 화면/컴포넌트를 **두 파일**로 나눕니다.

| 컴포넌트          | 웹 (`.tsx`)                    | 앱 (`.native.tsx`)   |
| ----------------- | ------------------------------ | -------------------- |
| **CourseScreen**  | 웹용 드래그 앤 드롭 (@dnd-kit) | 앱용 드래그 리스트   |
| **ResultsScreen** | 웹용 타임라인 레이아웃         | 앱용 네이티브 리스트 |
| **SpotMap**       | 카카오 지도 JS SDK             | react-native-maps    |

Expo가 **같은 이름**이면 웹일 때는 `.tsx`, 앱일 때는 `.native.tsx`를 자동으로 골라 씁니다.

## 🧠 상태 관리 방식 (쉽게 이해하기)

**상태(state)** 란 "지금 앱이 알고 있는 **정보**"예요.  
예: "로그인한 사용자是谁", "방금 만든 코스 결과", "코스 생성 중인지 여부" 등.

이걸 **여러 화면에서 공유**하려면 **Context**라는 "공유 보관함"을 씁니다.  
(비유: **회사 공지 게시판** — 어느 층에 있든 같은 게시판을 보면 "지금 회사에서 알려주는 정보"를 알 수 있어요.)

### 📦 Provider 감싸기 순서 (바깥 → 안쪽)

```
SafeAreaProvider          ← 화면 안전 영역 (노치 등 피함)
  └─ NetworkProvider      ← 인터넷 연결 여부
      └─ AuthProvider     ← 로그인한 사용자 정보 (user, 토큰)
          └─ SessionProvider  ← 앱 "준비 완료" 여부 (로딩 끝났는지)
              └─ PlacesProvider  ← 선택한 장소, 방금 만든 코스, "생성 중" 여부
                  └─ (화면들 + Toast 알림)
```

- **AuthProvider**가 없으면 → "지금 로그인한 사람이 누구지?"를 화면마다 따로 알 수 없어요.
- **PlacesProvider**가 없으면 → 코스 입력 화면에서 만든 결과를 "추천 결과" 탭에서 못 봐요.

그래서 **바깥 Provider가 먼저** 있어야, 안쪽 Provider와 화면들이 그 정보를 쓸 수 있습니다.

### 🔑 자주 쓰는 훅 (Context 사용법)

화면이나 컴포넌트에서 "공유 보관함"에 접근할 때 쓰는 함수들입니다.

| 훅               | 가져오는 것                                                       | 쓰는 화면 예                     |
| ---------------- | ----------------------------------------------------------------- | -------------------------------- |
| **useAuth()**    | `user`, `login`, `logout`                                         | 로그인 화면, 헤더(이름·로그아웃) |
| **usePlaces()**  | `lastGeneratedPlan`, `isCourseGenerating`, `setLastGeneratedPlan` | 홈, 코스 입력, 추천 결과         |
| **useSession()** | 로딩 카운트, 에러 메시지                                          | 전역 로딩 스피너, 에러 토스트    |
| **useNetwork()** | 온라인/오프라인 여부                                              | 네트워크 끊김 안내               |

정리하면, **"누가 로그인했는지"**, **"방금 만든 코스가 뭔지"** 같은 건 **Context**에 두고,  
화면은 **훅**으로 그 값만 가져와서 보여 주거나, 버튼 클릭 시 **Context에 저장**하는 방식입니다.

## 🚀 로컬에서 실행하기

### 필요 조건

- **Node.js** 18 이상
- **npm** (또는 yarn)
- (선택) Android Studio / Xcode — 에뮬레이터나 실제 기기 실행 시

### 1. 패키지 설치

```bash
cd front
npm install
```

### 2. 환경 변수 설정

프로젝트 루트(`front/`)에 `.env` 파일을 만들고, 백엔드 주소를 넣습니다.

```env
# 백엔드 API 주소 (로컬에서 백엔드 먼저 실행한 뒤 이 주소로 접속되게 설정)
EXPO_PUBLIC_API_URL=http://localhost:8000/otp

# 같은 Wi‑Fi의 휴대폰에서 테스트할 때는 본인 PC IP로 변경
# EXPO_PUBLIC_API_URL=http://192.168.0.10:8000/otp
```

`.env.example`이 있다면 복사해서 사용해도 됩니다.

```bash
# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env
```

### 3. 개발 서버 실행

```bash
npm start
```

터미널에 QR 코드와 단축키가 나옵니다.

| 키    | 동작                               |
| ----- | ---------------------------------- |
| **w** | 웹 브라우저에서 열기               |
| **a** | Android 에뮬레이터/기기에서 열기   |
| **i** | iOS 시뮬레이터에서 열기 (Mac 필요) |

직접 스크립트로 실행할 수도 있어요.

```bash
npm run web        # 웹
npm run android    # Android
npm run ios        # iOS (Mac + Xcode)
```

### 4. 동작 확인

1. **백엔드**가 `http://localhost:8000` (또는 `.env`에 넣은 주소)에서 떠 있어야 합니다.
2. **프론트**는 `npm start` 후 **w**로 웹을 열거나, 휴대폰에서 Expo Go 앱으로 QR 코드 스캔하면 됩니다.
3. 로그인/회원가입 후 홈 → 코스 생성 → 추천 결과까지 흐름이 보이면 정상 동작입니다.
